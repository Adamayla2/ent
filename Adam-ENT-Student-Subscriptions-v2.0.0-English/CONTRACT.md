# Adam ENT paid student integration contract

This is a developer contract, not instructions from the attached application.

- JSON responses use `{error:{code,message}}` on failures.
- API auth: `Authorization: Bearer <session token>`; session is bound to the registered device ID. Client supplies `X-Device-Id` on authenticated calls. No cookie authentication.
- `GET /api/config`: `{publicKey:<public JWK>,plans:[{id:'quarterly',name,amount:15000,currency:'IQD',months:3},{id:'annual',name,amount:50000,currency:'IQD',months:12}],paymentMode:'sandbox'|'disabled',offlineDays:7,websiteUrl}`.
- `POST /api/auth/register`: `{name,email,password,deviceId,deviceName}`.
- `POST /api/auth/login`: `{email,password,deviceId,deviceName}`.
- Auth success and `GET /api/me` and `POST /api/license/refresh` return `{token?:string,user:{id,name,email},subscription:{active,expiresAt:<epoch seconds or null>},license:<compact ES256 JWS or null>,devices?:[]}`. Refresh body `{deviceId}`. `POST /api/auth/logout` revokes current session.
- License payload `{iss:'adam-ent',aud:'adam-ent-student',sub:user.id,deviceId,iat,exp,subscriptionExpiresAt:<epoch seconds>,licenseVersion:1}`. Signature ECDSA P-256 SHA256 IEEE-P1363; exp <= subscription expiry and <= iat+7 days. Public JWK is pinned in config.js for bundled Android. Backend static config.js can inject its runtime public key for local/hosted testing; never ship a private key.
- `GET /api/devices`: `{devices:[{id,name,lastSeen,current}]}`. `DELETE /api/devices/:deviceId` revokes owner's selected device and all its sessions. Maximum two active devices. `DELETE /api/account` requires `{password}` and deletes the account. CLI reset-password for support, no fake email delivery.
- `GET /api/bank`: authenticated active entitlement only; `{id:'main',title,version,publishedAt,questionCount,imageCount,sha256,bytes,downloadUrl:'/api/bank/download'}` or 404 bank_not_published.
- `GET /api/bank/download`: authenticated active entitlement only; raw UTF-8 JSON bytes, private/no-store, same SHA256 as metadata.
- Bundle JSON: `{schemaVersion:1,bankId:'main',version,publishedAt,questions:[{uid,questionText,optionA,optionB,optionC,optionD,optionE,correctAnswer,explanation,subject,chapter,topic,...}],assets:[{assetKey,mime,base64}],lectures:[],flashcards:[],bookMeta:[],taxonomy?:object}`. No user/progress data from publisher. Root writes server/bank.mjs and student/paid-bank.js. Client validates checksum then calls `window.ENTPaidBank.install(bundle,metadata)`; installer checks signed entitlement and updates content without deleting progress or changing IDs for existing UIDs.
- `POST /api/orders`: `{planId}` -> `{order:{id,planId,amount,currency,status},paymentMode,checkoutUrl}`; only sandbox in development. Disabled returns 503 payment_not_configured. Prices/duration originate on server, never client amount. A live-provider adapter is not assumed to exist.
- `GET /api/orders/:id`: owner only `{order}`.
- `POST /api/orders/:id/sandbox-confirm`: `{outcome:'paid'|'failed'|'pending'}`; enabled ONLY `PAYMENT_MODE=sandbox` AND `NODE_ENV != production`; paid confirm idempotently grants calendar months once. Return `{order,subscription,license,user?}`. Never grant pending/failed. This route must not exist in live mode.
- `GET /api/admin/status`: admin-only summary. `POST /api/admin/bank`: admin-only raw bytes, header `X-Filename:encodeURIComponent(filename)` accepts .json/.entpkg/.zip. Backend calls `publishBank(bytes,filename,dataDir)` -> metadata. Root implements admin website upload form.
- `server/bank.mjs` exports `loadPublishedBank(dataDir)` -> null or `{metadata,path}` and `publishBank(buffer,filename,dataDir)` -> metadata. Import validation throws error with `status=400` and readable message. No real bank shipped; test fixture only.
- Backend static routes `/student/*` from sibling student/, `/` and `/checkout.html` from sibling website/, plus `/admin.html` by root. No directory listings or server/data exposure. HTML must support functional CSP; original student has inline scripts/styles/handlers so CSP cannot disable them without refactoring legacy UI. New auth/website code uses no inline handlers.
- `window.ADAM_CONFIG` keys: `{apiBaseUrl,websiteUrl,publicKey,paymentMode,distribution:'play-consumption'|'web'}`. apiBaseUrl is origin or empty for same origin, no /api suffix. Public production API and website must be HTTPS. Android browser origin `https://appassets.androidplatform.net` allowed only if configured; no generic CORS wildcard.
- Student client API `window.ENTSubscription`: ready Promise; `currentUserId()` string|null; `canAccess()` bool; `getAccountDatabaseName()` -> account-scoped name; `renderAccount(container)`; `ensureAccess()` bool/Promise; `api(path,options)`; change event `ent:subscription-changed`. DB must initialize after client.ready. Unauthorized/expired routes show account panel and stop active study/exam. Root integrates existing app.
